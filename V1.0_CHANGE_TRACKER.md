## Section 12 — Address / Profile Bug — 🔴 Not Started (root cause found)
`customer/src/pages/AddAddress.tsx` has ONE City input, but City is asked twice in practice: `handleStateChange` (line ~97) clears City and Pincode when State is picked, and the Pincode auto-fill (lines ~110–120) overwrites City. Planned fix: stop clearing City/Pincode on State change; optionally move Pincode first. Other apps (Captain, Admin) have no such issue.

## Section 13 — Instant Notifications — 🔴 Not Started (analysed, plan agreed in principle)
Cause: alerts are created inside the apps by polling (customer 2s, captain 30s) and only work while the app is open; no push service; captain "Ready for Delivery" checks a non-existent status (`ready_for_delivery`); admin gets no event alerts. Plan: Phase 1 — server writes a notification record per event, apps read their feed (~2s), admin bell; Phase 2 — Firebase push. Needs go-ahead + Firebase credentials.
